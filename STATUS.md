Rerun of `tests/test_sketch_gpu.py` immediately broke `test_torch_sketch_is_deterministic_given_seed` — two separate `TorchSketchProjector` instances with the IDENTICAL seed produced completely different outputs (100% of 4096 elements mismatched, not close at all). Root cause: chunk size determines where the (m, d) sign matrix gets split, and each chunk's RNG is seeded from its own start offset — so two instances must pick the SAME chunk boundaries from the SAME seed to produce the SAME output. Currently-free GPU memory drifts between calls (allocator caching, fragmentation), so the two instances (built moments apart) computed different chunk sizes and therefore completely different sign matrices. This wasn't a performance regression, it was an actual reproducibility/correctness bug introduced by the OOM fix itself.
